# Миграции схемы XClinic

Каталог содержит SQL-файлы, которые применяются **по порядку номеров** при запуске сервера.

## Зачем это, если есть Prisma

На компьютере клиники нет Prisma CLI — `prisma db push` там выполнить нечем. Установщик копирует только программу. Значит изменения схемы должны приезжать текстом и применяться самим сервером.

## Правила

1. **Имя файла:** `NNNN_kratkoe_opisanie.sql`, номер четырёхзначный, по возрастанию. Номер — это идентификатор в таблице `SchemaMigration`, менять его после выпуска нельзя.
2. **Файл применяется один раз.** Повторный запуск сервера его пропустит.
3. **Уже выпущенный файл не редактируют.** Раннер считает контрольную сумму и предупредит о расхождении, но применять заново не станет — у клиники изменение уже стоит. Нужна правка — новый файл.
4. **Изменение пишется дважды:** в `prisma/schema.prisma` (для Prisma Client и разработки) и здесь в SQL (для доставки клиенту). Расхождение между ними — главный риск этого механизма.

## Что в SQLite безопасно

Разрешено без пересоздания таблицы:

- `CREATE TABLE`
- `ALTER TABLE ... ADD COLUMN` — колонка обязана быть nullable **или** иметь константный `DEFAULT`
- `ALTER TABLE ... ADD COLUMN ... REFERENCES` — внешний ключ в новой колонке добавляется без пересоздания
- `CREATE INDEX`, `CREATE UNIQUE INDEX`, `DROP INDEX`

Требует пересоздания таблицы (**в этом проекте не применяем**):

- удаление колонки, смена типа или nullability
- внешний ключ на существующую колонку

## Как откатить

Отката вперёд нет: SQL применяется, запись в `SchemaMigration` остаётся. Настоящий откат — восстановление из резервной копии (блок Б1.2). Поэтому перед необратимыми миграциями снимок базы обязателен.

## Формат файла

Комментарии `--` разрешены. Разделитель инструкций — `;`. Файл применяется целиком в одной транзакции: при ошибке любой инструкции откатывается весь файл и запись о версии не появляется.
