# Moliya — oxirigacha (Kassa + Hisobot) — bajarish rejasi

> **Agent ijrochilar uchun:** superpowers:subagent-driven-development (tavsiya) yoki superpowers:executing-plans bilan, vazifama-vazifa. Qadamlar `- [ ]` belgisi bilan kuzatiladi.

**Maqsad:** Kassa va Hisobot klinika kun bo'yi ishlatadigan, raqamlari hamma joyda bir xil chiqadigan, tugallangan modulga aylansin.

**Arxitektura:** Qoida (2026-11-22, olti maslahatchi): **Kassa — bitta kunning naqd puli** (tushdi, chiqdi, yashikda, kun yopildi), **Hisobot — davr tahlili** (xizmatlar, olindi, xarajat, foyda, qarz, shifokor, bo'lim). Har raqam bitta manbadan va bitta nom bilan. Yangi ekran yo'q — mavjudlari ichida.

**Texnologiya:** React/TS/Vite/Tailwind (`pages/CashBook.tsx`, `pages/FinanceReport.tsx`), Express/Prisma (`backend/reports.ts`, `backend/server.ts`, `backend/billing.ts`), demo — `services/api.ts`, `services/demoData.ts`. Sinovlar: `backend/tests/api/*.ts` (`npm run test:api`), Playwright `e2e/*.spec.ts` (`E2E_BUILD=1 npx playwright test`), `e2e-demo/*.spec.ts` (`-c playwright.demo.config.ts`).

**Asos (spec):** olti maslahatchi hisobotlari (kassir, ega, DentaCRM, bozor, raqamlar, tanqidchi) — bu suhbatda, 2026-11-22; xulosasi shu faylning «Global cheklovlar» bo'limida.

## Global cheklovlar

- Yangi ekran yoki menyu bandi qo'shilmaydi; Kassa va Hisobot alohida modul bo'lib qoladi.
- So'zlar: Kassada «Kassaga tushdi», «Xarajat», «Yashikda»; Hisobotda «Xizmatlar», «Olindi», «Xarajat», «Sof foyda = xizmatlar − xarajat» (egasining 2026-11-14 qoidasi, o'zgarmaydi).
- Pul yozuvini tuzatish, o'chirish, qaytarish va chegirma — faqat ega (`backend/permissions.ts`).
- Registrator: faqat bugungi kassa, mayda naqd xarajat, to'lov olish.
- Har o'zgarish server + demo da bir xil ishlaydi.
- Sana — Toshkent kuni (`Asia/Tashkent`), UTC emas.
- Commit va o'rnatuvchi — faqat egasining roziligi bilan; demo saytga chiqarish — so'ramasdan.

## E'tibor beriladigan joylar (sinov bilan qoplanadi)

1. Yarim tun atrofida olingan pul — kerakli kunga tushishi (2-vazifa sinovi).
2. Qarzdor ismi bilan qidirilganda boshqa kundagi qarzi ham chiqishi (1-vazifa).
3. Kun yopilganda «topshirildi» summasi yashikdan ko'p bo'lmasligi (2-vazifa).
4. Bitta davr uchun Umumiy, Bo'limlar va Shifokorlar tablari bir xil jami ko'rsatishi (4, 5-vazifa).
5. Shifokor ulushi Hisobot va Xodimlar → Ulush da bir xil bo'lishi (3-vazifa).

### 2-vazifa: Kunni yopish — «Rahbarga topshirildi»

**Fayllar:** `pages/CashBook.tsx` (kunni yopish oynasi, `handleCloseDay`), sinov `backend/tests/api/moneybugs.ts` + `e2e-demo/kassa.spec.ts`.
**Interfeys:** oynada yangi maydon «Rahbarga topshirildi» (+ «Hammasini topshirdim» tugmasi), ostida «Kassada qoladi: X». Saqlashda: avval `api.cashMovements.create({ type: 'Encashment', amount: handed, method: 'Cash', note: 'Kun yopilishida topshirildi' })`, keyin yopish `countedCash = sanalgan − topshirilgan`.

- [ ] API sinovi: «kun yopilishida topshirilgan summa inkassatsiya bo'ladi va farqni o'zgartirmaydi» — sanalgan 500 000, topshirildi 400 000 → movement 400 000, closure.countedCash 100 000, difference avvalgisi bilan bir xil.
- [ ] e2e: «Hammasini topshirdim» bosilsa «Kassada qoladi: 0».
- [ ] Topshirilgan > sanalgan bo'lsa saqlash tugmasi o'chiq va qizil izoh.
- [ ] Sinovlar o'tishi.
